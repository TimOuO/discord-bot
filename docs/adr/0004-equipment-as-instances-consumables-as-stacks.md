# 裝備改用「一件一列」的實體模型，消耗品/材料維持可堆疊庫存

原本所有道具都存在 `Inventory`（`userId` + `itemId` + `quantity`，同名合併成一列），`EquippedItem` 也是指向道具**種類**。要做裝備強化時這個模型表達不出「+7 的屠龍劍」——強化等級不管掛在哪裡都會變成整疊共用，而且裝備欄根本分不出玩家裝的是 +7 那把還是 +0 那把。

因此新增 `ItemInstance`（一件裝備一列，帶 `enhanceLevel`），`EquippedItem` 改成指向實體。**但只有武器/防具/飾品變成實體，藥水/魚/材料維持原本的可堆疊 `Inventory`**：釣到 200 條魚拆成 200 列只是負擔，而個體之間本來就沒有任何差異，區分它們沒有意義。代價是背包同時存在兩種儲存形式，`getInventory()` 回傳的是兩者的聯集型別、呼叫端要用 `kind` 分辨。

## 考慮過的其他做法

- **強化等級掛在 `Inventory` 上**：改動最小，但同名裝備會共用同一個強化等級，玩家沒辦法同時持有 +7 跟 +0 的同一把劍。
- **掛在 `EquippedItem`（裝備欄）上**：最便宜，但語意會變成「強化的是欄位不是裝備」——換裝時強化要嘛憑空消失、要嘛新武器白撿 +7，兩種都很怪。
- **所有道具都變成實體**：模型最一致，但堆疊類道具的數量動輒上千，且背包顯示、賣出數量、鍛造扣料全部要改成數列數，反而更複雜。

## 連帶的好處

`equipItem` 原本有一段「手上剩下的數量夠不夠再裝到另一個欄位」的檢查（要扣掉已經佔用在其他欄位的件數）。改成實體之後這段整個刪掉——一件實體本來就只能出現在一個欄位，靠 `EquippedItem.itemInstanceId` 的 unique 約束保證，不需要自己算數量。
